You Are a One-Man Army

As a solo software developer spinning up an MVP, having access to the entire triad of Claude Desktop capabilities — Chat, Cowork, and Code — gives you a massive competitive advantage. You are effectively using Claude as your product manager, backend engineer, QA tester, and operations team all at once.

Critical trap to avoid: Do not treat Chat, Code, and Cowork as interchangeable. Each interface uses a distinct execution model designed for a specific job. Mixing them up wastes time and kills momentum.

Part 1 — The 5Ws of Your Claude Setup

Who

The Roles Assigned

  • Chat — Strategist & Designer. Handles non-coding logic, UI flow mockups, and high-level architectural brainstorming.
  • Code — Full-Stack Developer. Operates inside your terminal, directly writes code, runs test suites, and handles Git.
  • Cowork — Operations Agent. Browses the web, organizes files, syncs with APIs, and manages data inside a sandboxed VM.
What

Building The MVP

Speed-to-market, lean codebases, clean folder structures, and automated operational tasks are your priorities. Every decision should serve the goal of shipping fast without scope creep.

Where

The Execution Pods

  • Chat — Inside the Claude Desktop GUI (cloud-sandboxed).
  • Code — Inside your local terminal/IDE, mapped to your project root.
  • Cowork — Claude Desktop GUI with safe access to local folders and your Chrome browser.
When

Linear Phase Swapping

You move sequentially — never jumping back and forth randomly:

Chat Code Cowork
Why

Slashing Non-Code Admin

Solo devs typically spend only 30% of their time writing code and a painful 70% on setup, debugging, documentation, data population, and admin tasks. The Triad slashes that 70% close to zero.

Chat Engine

Phase 1: Product Scoping & Architecture

Isolated Sandbox

Before touching a line of code, you must lock down the scope. MVPs fail when scope creep happens. Use the Claude Chat interface as a Senior Technical Product Manager to assemble high-fidelity specifications that will guide the entire build.

1

Initialize Strategy Project Pod

Open Chat → Projects. Create a project named [MVP Name] - Strategy. Upload your initial brain-dump, raw notes, market analyses, or napkin-sketches directly into the Project Knowledge Base so Claude has full context.

2

Generate the PRD

Prompt Claude to act as a Senior Technical Product Manager. Instruct it to lock down tech stack choices and output the plan as a persistent Artifact you can reference throughout the project.

"Review my project notes. Generate a lean Product Requirement Document (PRD) and a step-by-step technical architecture plan for an MVP. Use simple tech stack choices (e.g., Next.js, Supabase, Tailwind). Output the PRD as an Artifact."
3

Refine Until Architecture is Flawless

Iterate with Claude inside the Chat Project until every part of the architecture is agreed upon and airtight. Challenge edge cases, data models, and API design choices here — not mid-build. Do not proceed to Phase 2 until you are fully satisfied.

4

Set Persistent Memory Guardrail

Open the Customize panel inside the project view. Add a system-level instruction that locks Claude to your agreed architecture for every future conversation inside this project:

"Always adhere to the architectural guidelines outlined in the PRD artifact."

Claude Code CLI

Phase 2: Rapid Codebase Generation

Terminal Native

Your architectural blueprint is locked. Now hand it off to the terminal agent. Do not copy-paste code snippets from Chat. Use the dedicated Claude Code CLI — it operates directly inside your repository, runs tests, reads console logs, and self-corrects without you babysitting it.

1

Spin Up Workspace & Boot Agent

Open your terminal, navigate to your blank project folder, spin up your base framework, then launch the Claude Code agent from your project root:

npx create-next-app@latest my-mvp-app && cd my-mvp-app
claude
2

Feed the PRD into the CLI Loop

Provide your first instruction by referencing the PRD from Phase 1. Claude Code will scaffold the project structure accordingly:

"Initialize the project structure. Create the primary database schema helper files for Supabase and set up the main layout component according to our PRD guidelines."
3

The Self-Correction Testing Loop

When building features or fixing bugs, instruct Claude Code to execute its own test suite. It will use its internal verification loops to read console output and resolve errors automatically before committing:

"Create the authentication page components. Once written, run `npm run test` or check for compilation errors, read the console logs, and fix any breaking changes before committing to git."
4

Commit with Conventional Commits

Let Claude Code write and execute the git commit for you — following conventional commit format for a clean, professional history:

"Review my recent changes, write a clean commit message following conventional commits, and commit it."
Cowork Agent

Phase 3: Launch Ops & Data Seeding

VM & Browser

Your app is built but it's empty. You need mock data, competitor analysis, or initial database seeding. This is where Cowork shines — it can control your browser, read and write local files, and interact with web services on your behalf.

1

Establish the Local File Vault Bridge

Open Cowork → Projects in Claude Desktop. Create a project and point its file sandbox access to a dedicated external folder on your computer — such as /assets or /seeding — so Cowork can read and write files there safely.

2

Connect the Browser Agent

Ensure your Chrome connection extension is active. Set the mode selector to "Follow a plan" or "Ask before acting" depending on your comfort level — "Ask before acting" is recommended for your first few runs.

3

Autonomous Web-to-File Data Extraction

Dispatch Cowork to scrape real data from the web and compile it into a structured file, ready for seeding:

"Navigate to [Competitor Website or Directory]. Find the top 20 trending items/data points. Extract their titles, descriptions, and image links. Compile this data into a clean `seed_data.json` file and save it directly into my shared local folder."
4

Push the Data into Your Database

Once the seed file exists in your shared folder, you have two options:

  • Switch to Code and prompt it to read the JSON and insert it directly into your Supabase/Firebase tables via the CLI.
  • Or keep Cowork running and have it log into your Supabase/Firebase dashboard in Chrome, then paste or upload the data directly through the UI.
Routines & Schedules

Part 3 — The Automation Blueprint

Hands-Free

As a solo developer, you can't afford to waste time on repetitive daily checkups. You must automate your routines. Set these up once and let them run — freeing you to focus entirely on shipping product.

1. Codebase Maintenance — Code Routines

In the Code section, configure a daily Routine that triggers via the CLI or automatically at midnight to keep your repo healthy.

// Daily — Vulnerability Audits & Linter

"Check the repository for security vulnerabilities (`npm audit`), look for outdated non-breaking dependencies, run the linter to ensure formatting rules are met, and generate a summary markdown file detailing what needs updating."

2. User Feedback Synthesis — Cowork Scheduled

In the Cowork section, switch to the Scheduled tab and set up this recurring task to automatically surface user pain points every morning.

// Every day at 08:00 AM

"Open Google Sheets/Airtable where my MVP's user feedback form is connected. Read the new entries from the last 24 hours. Connect to Chrome, search for any mentions of our app on Twitter/X, and compile a 'Daily Pulse Report' artifact highlighting critical bugs and feature requests."

3. Competitor Pricing & Feature Watch — Cowork Scheduled

Stay ahead of the market without lifting a finger. Cowork checks your competitors every week and alerts you to any changes in their pricing or feature set.

// Every Monday morning

"Go to our top 3 competitors' landing pages. Take a screenshot of their pricing tables. Compare them to the screenshots from last week. Write a summary detailing if they changed their pricing models or introduced new features."

Summary — The Ideal Developer Flow

To maximize efficiency, keep this simple mental model in mind. When you're unsure which surface to use, ask yourself one of these three questions:

Use Chat

When you're stuck on a feature concept or DB architecture.

Open a Chat Project to brainstorm, design, and get answers — without touching code.

Use Code

When you're ready to write code, refactor, or squash a compiler bug.

Run claude in your terminal. Let it build, test, and commit autonomously.

Use Cowork

When you need to scrape data, run browser testing, or set up automation.

Toggle to Cowork in Claude Desktop to handle all ops, assets, and scheduled tasks.
